# 安全合规 · 敏感信息管理

> 硬性要求：**API 密钥等敏感信息不得出现在公开仓库中，必须通过环境变量配置。**

本文档记录该要求的落地方式、本次审计结论、密钥生成与轮换流程，以及提交前的自检方法。

---

## 一、政策

| 编号 | 规则 |
|---|---|
| P1 | 仓库内**不得出现任何真实密钥**——包括代码常量、配置文件、文档、注释、示例文件 |
| P2 | 所有密钥**只能**通过环境变量注入；代码只读取 `process.env.*`，不提供内置默认值 |
| P3 | 只提交**模板** `.env.example`，其内容必须是占位符或留空，不得是可用的真实值 |
| P4 | `.env` 及其所有变体（`.env.local` / `.env.production` …）一律被 `.gitignore` 忽略 |
| P5 | 密钥缺失或格式非法时**直接报错**（fail-closed），绝不退化为"公开的默认密钥" |
| P6 | 泄露过的密钥**必须轮换**；仅从代码中删除是无效的——历史与缓存中仍可提取 |

## 三、已修复的问题

### 1. `src/lib/crypto.ts` —— 移除硬编码兜底密钥

**修复前**：`ENCRYPTION_KEY` 缺失时静默使用一个写死在源码里的 64 位十六进制密钥。
该值同时出现在公开的 `.env.example` 中，等于**加密形同虚设**——任何人都能用这把公开密钥解开数据库里的 API Key。

**修复后**：改为惰性获取 + 严格校验，缺失或格式非法直接抛异常：

```ts
function getKey(): Buffer {
  const raw = process.env.ENCRYPTION_KEY
  if (!raw) throw new Error('缺少环境变量 ENCRYPTION_KEY，拒绝以不安全方式启动。…')
  if (!/^[0-9a-fA-F]{64}$/.test(raw)) throw new Error('环境变量 ENCRYPTION_KEY 格式非法：需为 64 位十六进制字符串（32 字节）。…')
  return Buffer.from(raw, 'hex')
}
```

> 用「惰性函数」而非模块顶层常量，是为了避免构建阶段（`next build`）因缺少环境变量而失败，同时保证**任何一次实际加解密都经过校验**。

### 2. `src/lib/auth.ts` —— 移除 `JWT_SECRET` 兜底值

**修复前**：`const SECRET = process.env.JWT_SECRET || 'dev-secret'`
使用固定的公开默认值时，**任何人都能伪造合法 token 冒充任意用户登录**。

**修复后**：`getSecret()` 要求 `JWT_SECRET` 必须存在且长度 ≥ 16，否则抛错。

### 3. `server/mcp-server.ts` —— 统一密钥来源

**修复前**：`encrypt_data` 工具自行拼凑密钥
（`process.env.ENCRYPTION_KEY!.padEnd(64, '0').slice(0, 64)`），
既会在变量缺失时崩溃，又因补位方式不同而产生**与主加密模块不一致的密钥**。

**修复后**：直接复用 `src/lib/crypto.ts` 的 `encrypt()`，全项目只保留一处密钥派生逻辑。

### 4. `.env.example` —— 占位符化

原文件第 10、11 行写入了**真实可用的密钥值**（与源码兜底值相同）。现已改为留空 + 生成说明，并在文件头部加入醒目警示。

### 5. `.gitignore` —— 扩大忽略范围

```gitignore
.env
.env.*
!.env.example
```

新增 `.env.*` 通配（覆盖 `.env.production` / `.env.development` 等此前**未被忽略**的变体），并补充 `*.pem`、`*.key`、`*.p12`、`*.pfx`、`.npmrc`、`credentials.*`、`secrets/` 等凭据类文件的忽略规则。

## 四、环境变量清单

### 必须配置（缺失会直接报错）

| 变量 | 要求 | 说明 |
|---|---|---|
| `ENCRYPTION_KEY` | 64 位十六进制（32 字节） | 用于 AES-256-GCM 加密用户 API Key |
| `JWT_SECRET` | ≥ 16 字符，建议 32 字节随机值 | 用于签发 / 校验登录令牌 |

### 可选（按需配置，留空则相关功能降级）

| 变量 | 用途 |
|---|---|
| `DATABASE_URL` | 数据库连接（默认 `file:./dev.db`） |
| `DEFAULT_AI_PROVIDER` / `DEFAULT_AI_BASE_URL` / `DEFAULT_AI_API_KEY` / `DEFAULT_AI_MODEL` | 系统默认大模型 |
| `EMBEDDING_BASE_URL` / `EMBEDDING_MODEL` | 向量检索端点 |
| `RERANKER_BASE_URL` / `RERANKER_MODEL` | 重排端点 |
| `WHISPER_BASE_URL` / `OCR_BASE_URL` / `TTS_BASE_URL` / `SD_BASE_URL` | 多模态端点 |
| `NETEASE_API_BASE` / `NETEASE_COOKIE` | 音乐服务 |
| `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 可选实时通道 |

> ⚠️ 注意：`NEXT_PUBLIC_` 前缀的变量会被**打包进浏览器端代码**，任何人都能看到。
> **绝不要把任何密钥放进 `NEXT_PUBLIC_` 变量**（它只适合放公开配置，如站点地址）。

## 五、生成与配置密钥

```bash
# 生成一个 32 字节（64 位十六进制）随机值
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

# 复制模板并填写（.env 不会被提交）
cp .env.example .env
```

**分别生成两个不同的值**，不要复用同一个字符串：

```dotenv
ENCRYPTION_KEY="<第一个随机值>"
JWT_SECRET="<第二个随机值>"
```

## 六、密钥轮换

### JWT_SECRET 轮换

改 `.env` 里的值 → 重启服务即可。副作用：所有已登录用户的会话失效，需要重新登录。

### ENCRYPTION_KEY 轮换（**有额外步骤**）

数据库里已有的密文是用旧密钥加密的，**直接改密钥会导致这些数据无法解密**（用户配置的 API Key 失效）。正确流程：

1. **备份** `.env` 与数据库文件
2. 用旧密钥解密 → 用新密钥重新加密 → 写回数据库
3. 更新 `.env` 中的 `ENCRYPTION_KEY`
4. 验证：用新密钥能成功解出原有数据

本项目的实现要点：`AiProvider.apiKeyEnc` 字段存放的就是密文，
格式为 `base64(iv):base64(authTag):base64(ciphertext)`，可用 `src/lib/crypto.ts` 的 `decrypt()` / `encrypt()` 完成迁移。

## 七、提交前自检

```bash
# 1) 确认没有 .env 之类的敏感文件被跟踪（输出应只有 .env.example）
git ls-files | grep -E "^\.env"

# 2) 确认代码中没有硬编码密钥
git grep -nE "sk-[A-Za-z0-9]{20,}|ghp_[A-Za-z0-9]{20,}|AKIA[0-9A-Z]{16}|-----BEGIN[A-Z ]*PRIVATE KEY"

# 3) 检查本次改动是否意外带入了密钥
git diff --cached | grep -iE "key|secret|token|password" | head

# 4) 扫描历史（发布前做一次）
git grep -I -nE "sk-[A-Za-z0-9]{20,}|ghp_[A-Za-z0-9]{20,}" $(git rev-list --all)
```

以上第 1、2、4 条命令的输出都应为空（第 1 条仅允许出现 `.env.example`）。

## 八、如果密钥已经泄露

**顺序很重要，不要只做前两步就以为没事了：**

1. **立即在服务商处吊销 / 重置该密钥**（如 DeepSeek、OpenAI 控制台）——这是唯一真正止血的动作
2. 从代码与配置中删除
3. 轮换本地 `ENCRYPTION_KEY` / `JWT_SECRET`（按第六节流程）
4. 若已 push：改写 Git 历史（`git filter-repo`）并**强制推送**，同时提醒协作者重新克隆
5. 记住：**历史一旦推送，仅靠后续提交删除是无效的**，密钥仍可从旧提交中提取

> 本项目当前状态：历史中**从未出现过真实密钥**，`.env` 从未被提交，因此不存在已泄露的密钥。
